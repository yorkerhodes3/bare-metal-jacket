Operating thesis

Simple first. Safe by design.

Prove the complete release loop before adding distributed coordination. Keep high-privilege operations behind narrow, replaceable adapters from day one.

01

Docker-native

Accept a Dockerfile or immutable OCI image. Avoid a broad runtime matrix until the release path is reliable.

02

Privilege separated

The API never owns Docker access. Build and runtime authority stays inside narrowly scoped adapters.

03

Release aware

Building, scheduling, health checking, and activating are distinct, auditable state transitions.

04

Observable

Deployment events, logs, metrics, traces, and audit records are first-class platform output.

Entry boundary

Console / API

Authenticates requests and records desired state. It cannot run arbitrary infrastructure commands or access the Docker socket.

  • OIDC authentication and project authorization
  • Versioned resource contract
  • Idempotent deployment requests

Key finding

The closest references are not the final architecture.

Coolify and Dokploy demonstrate feature breadth. Dokku and CapRover demonstrate mature simplicity. This project differentiates through explicit state, privilege separation, provenance, and bare-metal recovery—not a larger template catalog.

Known hard parts

The dashboard does not hide the risks.

A polished experience is only valuable when isolation, failure recovery, and state compatibility are honest.

Isolation

Docker is not a hostile-tenant sandbox.

The MVP is single-organization. Public tenancy requires a new threat model and stronger execution boundaries.

State

Volumes constrain safe rollout.

Exclusive storage and incompatible migrations can make overlap or rollback unsafe even when containers are healthy.

Builds

Dockerfiles execute untrusted code.

Dedicated workers, resource bounds, egress policy, short-lived credentials, and log redaction are required.

Operations

Recovery must work on a clean host.

Backups count only after image digests, secrets, audit history, deployment, and rollback survive a restore drill.

The first demonstration

One Dockerfile. One node. One trustworthy release path.

Build a narrow vertical slice, prove failure recovery, and expand only when the next layer of complexity has a measured reason to exist.
